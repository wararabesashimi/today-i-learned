リージョンはAWSがサービスを提供している国や拠点を指す。<br>
リージョン同士は地理的に離れた位置に存在する。

アベイラビリティゾーン(AZ)は複数のデータセンター(DC)から構成され、リージョンは複数のAZから構成される。<br>
> リージョン > AZ > DC

各AZ同士は地理的、電源的に独立した場所にあり、最低でも数十kmは離れているらしい。<br>
仮に災害等でAZの一つが使用不可になったとしても、リージョン内の他のAZでサービスを継続することができる。<br>
→ 高耐久性、高信頼性の担保

ただし当然ながらユーザー側が単一のAZにインスタンスを立てていた場合はオンプレとなんら変わりない。<br>
→ 冗長的な `マルチAZ` で高耐久性を確保する。
> AZ 1にインスタンス 1、AZ 2にインスタンス 2を立てて、DBをメインからサブへレプリケーションする等すると、異なるサーバーへのアクセスも同じDBのデータを返すことができる。

### 09-23

`git remote add <リモート名> <リモートリポジトリのリンク>` でorigin以外のリモートリポジトリを保持しておくことができる。<br>
→ リンクには `https` か `SSH` のものを貼り付ける。

pushする時には以下の様に追加したリモートリポジトリ名を指定する。
```
git push <リモート名> <ブランチ名>
```

余談だが、`git push` のように引数を省略した場合は、
```
git config --global push.default
```
で指定した設定でpushを行う。<br>
push.defaultの設定を変更したい場合は以下のコマンドで設定。
```
git config --global push.default simple
```

### 09-24

`Virtual Private Cloud(VPC)` とは、AWSの中核的サービス。<br>
AWSのほとんどのサービスを利用するためには前提として必要。

一つのAWSアカウントに複数のVPCを立てることも可能だが、最近の構成は1アカウントに1VPCとして検証環境や開発環境、本番環境で別々のアカウント(VPC)を用意することで、他環境への影響をなくす手法が取られることが多い。

VPCの中にはサブネット、そしてEC2やECS等が置かれるが、一昔前は単一VPCに環境別の複数のサブネット(EC2, ECS)を置いて、管理することも多かったらしい。<br>
→ 単一VPCだとVPC自体に障害が起きた場合、全ての環境に影響が出てしまう可能性があるため、現在では望ましくない。

`CloudTrail` のログもアカウントごとのため、環境別のログが判別しづらくなる問題もある。<br>
さらにアカウントごとに分ければ、環境別の料金も一目でわかる。

→ **1アカウントに1VPCがベストプラクティス**

VPCには、IPv4のCIDR(オプションでIPv6も可)を振り分ける必要がある。

指定できないCIDRには以下の4種類がある。
```
0.0.0.0/8
127.0.0.0/8 (内部ホストループバックアドレス範囲)
169.254.0.0/16 (リンクローカルアドレス範囲)
224.0.0.0/4 (マルチキャストアドレス範囲)
172.17.0.0/16(Cloud9とSageMakerの範囲)
```

また、 `RFC1918` によって定められているプライベートIPアドレスの割当の範囲外をVPC内のCIDRに指定しても良いが、同じIPアドレスで外への通信時にプライベート空間に接続されてしまうため、基本は `RFC1918` の範囲内でCIDRを定める。
```
10.0.0.0	-	10.255.255.255 (10.0.0.0/8)
172.16.0.0	-	172.31.255.255 (172.16.0.0/12)
192.168.0.0 -   192.168.255.255 (192.168.0.0/16)
```
